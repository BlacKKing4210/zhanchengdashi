# F-ZC-HOME-001 / v1.0 implementation source

Producer direction: 2026-09-24 current user request and follow-up. Implement the existing locked bottom-left slot as Home, retaining the approved B skin, battle terrain, castle and animal art. Reference screenshot supplies interaction principles only, not assets or commercial identity.

## Player contract
- Each flat-top hex is one building. Four types: residence (blue), dining (orange), entertainment (lilac), sport (lime); castle uses cream. Type and price remain visible before unlocking. Unlock only adjacent to owned land. Axial ring prices are stable per plot: 100 * 3^(ring-1) * [0.5,1.5], first ring 50..150. Reveal one frontier ring beyond owned land. Configurable safety limit 8 rings.
- Castle is initially owned. Owned animal species become residents (one per unlocked animal card, not duplicate cards). Assign homes with capacity 1..5, overflow stays in castle. Hide animals inside buildings. Route outdoor travel only along shared hex vertices/edges, with a short door crossing on entry/exit. Day: random meals and exercise; night: random entertainment and then rest. Preview day/night follows a 240-second cycle, independent of real-day rewards. Completion bubbles are 85% positive, drawn faces rather than font emoji.
- Unlock spends wallet gold atomically and grants exactly one gacha ticket immediately, once per plot. Coins and tickets use the existing account balances and icons.
- Each non-castle building produces one themed item per eligible real day. Hidden value equals rounded price/10 up to price 150; thereafter round(15 + 12*ln(price/150)), capped at 100. Thus higher unlock prices never reduce value and yield/cost diminishes. Four corresponding items: soft pillow, meal basket, music box, sports medal. No estimated value on player UI.
- At home entry show all eligible daily items, then explicit exchange action reveals random coins (80%..120% of each item's hidden value) and independent one-ticket chance value*0.1/100 per item. Castle directly contributes 100 coins + 1 ticket per day. All settlement is once-only, persisted atomically with balances. No reroll on reopening or retrying.
- Beijing calendar day (UTC+8), at most latest 3 days inclusive. New homes start on initialization day. New plots produce from the next calendar day. Missed days outside the three-day window expire. Same-day repeated entry cannot claim twice. No client-clock authority for online rewards; snapshot comes from server.
- Home tab dot appears for a claim or an adjacent affordable plot. Header shows gold and tickets. Support scroll/pan, zoom, reset camera; keep 720x1280 and 360x640 readable. Details show type, capacity/activity, daily item and eligibility, never hidden value. Reward list must paginate for large accounts.

## Final implementation notes
The home service uses an isolated child RPC node so the deployed battle RPC declaration order remains unchanged. Client state requests wait for any earlier profile save; late replies rebase the local currency changes earned while waiting. The home tab refreshes from the server across UTC+8 midnight even while another page is open, with retries throttled when the device clock disagrees. Touch dragging follows only its initiating finger.

For independent local review, launch the debug build with `-- --home-preview`. This opens the same home page with a separate `user://home_preview_v1.json` (600 starting coins, 10 tickets), skips account auto-login and normal rank/profile persistence, and never deploys a server. The normal home entry remains capability-gated until the authorized cloud service is updated. This preview is for home acceptance; it does not promise persistence for every other game mode.
