# 账号切换与新建账号功能设计

版本：v1.0（2026-07-18）

## 目标

将无效的“注销账号”入口替换为账号切换。玩家可以查看当前安装凭据拥有的全部服务器档案，看到每个档案的 UserID、段位和动物总数量，并通过黄色“新建账号”按钮创建一份全新游戏进度。

## 范围与边界

- 一个安装 ID 最多拥有 8 个档案；账号集合的读取与切换必须通过有效长期令牌和当前短会话授权。
- 档案资料继续以服务器为权威。客户端只显示服务器返回的摘要，不能合成、伪造或修改其他档案资料。
- 手动账号密码登录成功后，服务器把该账号加入当前安装的可切换集合；密码不进入本机凭据、账号列表或服务器摘要。
- 切换账号时，旧会话立即失效；客户端必须用新档案完整替换卡牌数量、卡牌星级、编组、抽卡券、段位和分段获胜记录。
- 新建账号由服务器按当前卡表配置生成 8 个普通动物、新手金矿与防御塔、10 张抽卡券及青铜 1 星资料。客户端不提交任何初始资源数值。

## 交互与状态

1. 玩家在大厅点击中央基地，进入“设置与账号”。
2. 已登录时，原“注销账号”按钮显示为“切换账号”。
3. 点击后显示全部所属档案；每一项显示 UserID、段位、动物数量，当前档案标记“当前”。
4. 点击非当前档案，服务器验证归属、失效旧短会话、签发新短会话并同步新档案资料，然后返回账号中心。
5. 点击黄色“新建账号”，服务器创建新档案并立即切换；客户端提示“已新建账号，开始新的游戏进度”。
6. 连接失败、会话失效、非所属档案或达到 8 个账号上限时，保留当前档案并显示明确错误提示。

## 数据来源

- 账号集合、当前档案与短会话：`PlayerAccountStore`。
- 账号列表 RPC、切换 RPC、新建账号 RPC 与新手资料：`OnlineRoom`。
- 卡表驱动的新手动物和建筑：`ConfigDB` 的 `cards` 表。
- 账号中心列表与本地资料替换：`Main`。

## 部署入口

Windows Desktop 导出保持进入客户端主场景；带有 `dedicated_server` 特性的专用服务器导出必须进入 `scenes/server.tscn`。启动分流器负责在两种运行模式间选择入口，确保账号创建、列表和切换 RPC 由真实监听 UDP 24567 的服务器处理。

## 验收

- 同一安装能列出全部所属档案，摘要包含 UserID、段位和动物总数量。
- 新建账号后账号数增加 1，且新账号显示青铜 1 星、10 张抽卡券和新手动物。
- 切换档案后，旧卡牌和段位不会残留到新档案；切回后原进度保持。
- 其他安装不能读取或切换该安装的档案。
- 账号存储回归、ENet 联机回归和 Godot 项目解析通过。
