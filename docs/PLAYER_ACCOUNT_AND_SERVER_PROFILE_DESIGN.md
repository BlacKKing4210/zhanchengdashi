# 玩家账号与服务器资料设计

版本：v1.4（2026-07-22）

## 默认设备账号

- 客户端首次启动时生成 32 字节随机“安装 ID”，保存在 `user://client/device_account.json`，不读取 MAC、硬盘序列号或其他物理地址。
- 首次连接服务器时，客户端用安装 ID 和空令牌发起设备认证。服务器创建游客账号、生成不可修改的 `user_id`，并仅在这次响应中返回 32 字节随机长期登录令牌。
- 客户端把长期令牌与标准化 `server_host:server_port` 一起保存；游戏进入大厅后会立即自动连接服务器。旧版凭据或服务器地址变化时，保留安装 ID、清除旧令牌，再对新服务器执行首次设备认证，无需玩家点击中央基地或重复输入账号密码。
- 服务器只保存安装 ID 的 SHA-256 摘要、随机盐和长期令牌哈希，不保存安装 ID或令牌明文。网络连接仍使用短期会话令牌访问玩家资料。
- 玩家通过账号与密码手动登录成功后，服务器才允许把该账号加入本机档案集合并设为当前档案；对未绑定安装或失效令牌会签发新的长期令牌。客户端继续只保存安装 ID、服务器地址和长期令牌，不保存账号密码明文。
- 账号中心不再提供“注销账号”。因为长期令牌会立即恢复同一档案，旧入口容易让玩家误以为注销无效；它改为“切换账号”。
- 删除应用数据或丢失本机凭据会失去自动登录能力；正式发行前应补充账号绑定、令牌轮换和跨设备找回流程。未知安装 ID 携带非空令牌时必须被服务器拒绝，不能被当作自动注册。

## 本机账号切换

- 一个安装 ID 可拥有最多 8 个独立服务器档案。账号集合仅由已认证的安装 ID 与长期令牌查询；不会向客户端暴露其他设备的档案。
- 点击“切换账号”后，服务器返回该安装 ID 的全部档案摘要：UserID、当前段位、星数与动物总数量。当前档案单独标识；点击其他档案后，服务器撤销旧短会话并签发新短会话，再同步该档案资料。
- 列表底部使用黄色“新建账号”按钮。服务器为该安装创建全新档案，按当前卡表发放新手动物、基础建筑、10 张抽卡券与青铜 1 星资料，然后立即切换并开始新游戏。
- 手动账号密码登录成功后，会把该账号加入当前安装的可切换集合并设为当前档案；密码不会写入本机或账号列表。

## 分段获胜阵容

- 每次段位赛获胜后，客户端按“开局时所在分段”记录获胜者的 8 张卡组、对应卡牌等级、星数、UserID 和记录时间。
- 本地记录继续保存在 `user://rank_mirror_db.json`，同时作为玩家服务器资料中的 `rank_mirrors` 字段上传，换设备登录同一账号后可恢复。
- 服务端按分段校验数据结构，每个分段最多保存 15 条，卡组最多 8 张，卡牌等级最低为 1；未知类型、空卡牌 ID 和超量数据会被过滤。
- 服务器资料尚无获胜阵容但本机已有历史记录时，不用空数据覆盖本机记录；下一次资料同步会把本机历史记录补传服务器。

## 目标

每名玩家拥有服务器生成且不可修改的 `user_id`、唯一账号和密码凭据。密码只保存加盐哈希。卡牌拥有数量、卡牌星级、出战编组、抽卡券、段位星数与 ELO 均由服务器资料作为权威数据。

## 模块边界

- `PlayerAccountStore`：仅运行在服务端，负责账号注册、密码校验、安装所属账号集合、会话令牌和 JSON 持久化。
- `OnlineRoom`：负责账号 RPC、把网络连接映射到已登录用户、为新档案生成服务器侧新手资料，以及限制资料写入只能作用于当前会话用户。
- `Main`：启动时主动连接，展示账号中心和账号切换列表、调整本机音量；不保存密码，不把客户端资料当作服务器权威数据。
- 账号数据库默认位于服务端 `user://server/player_accounts.json`，可用测试路径覆盖。

## 数据结构

账号记录包含 `user_id`、规范化账号、密码盐、密码哈希、创建/更新时间和 `profile`。资料字段：

- `card_counts`：卡牌 ID 到拥有数量。
- `card_levels`：卡牌 ID 到星级，最小 1。
- `deck`：最多 8 个卡牌 ID。
- `gacha_tickets`：非负整数。
- `rank_stars`、`elo`：非负整数。

## 页面与跳转

主界面点击中央基地 -> 账号中心；基地保持可点击，但不再承担触发自动登录的职责。游戏启动后会在大厅后台自动连接：首次或切换到新服务器时，客户端先以空令牌申请默认设备账号与 UserID；有效令牌则恢复当前档案。未登录时账号中心提供账号、密码输入以及注册/登录按钮；登录成功后显示服务器生成的 UserID，并把当前安装绑定到该账号供下次启动自动登录。已登录时，“切换账号” -> 账号列表；列表项 -> 服务器撤销旧会话、同步所选档案并返回账号中心；黄色“新建账号” -> 服务器创建新手档案、同步资料并开始新游戏；“绑定账号” -> 显示账号密码输入，可注册或登录命名账号并切换到该账号。关闭 -> 主界面；玩家协议 -> 协议文本层；协议返回 -> 账号中心。音乐与音效按钮即时切换并显示当前状态。

账号中心显示 UserID 和服务器同步状态。未登录时显示“未登录”，客户端不得伪造 UserID 或宣称资料已同步。

## 安全与失败处理

- 账号比较不区分大小写，长度 3-32；密码长度 8-72。
- 密码使用随机盐和多轮 SHA-256 派生；数据库不保存明文密码和会话令牌。
- 登录失败使用统一错误，不暴露账号是否存在。
- 本地设备凭据只含随机安装 ID、服务器地址和随机长期令牌；账号密码只用于当次手动登录请求，不写入本地凭据文件。
- 账号列表只返回当前安装凭据所属的摘要字段；切换目标必须属于该集合，且每个安装最多保留 8 个可切换档案。
- 资料保存采用临时文件替换；字段在服务端归一化，负数和未知类型被拒绝或修正。
- 登录后客户端先应用服务器资料，再以变更检测方式同步卡牌数量、卡牌星级、编组、抽卡券和段位资料；未登录状态不上传。
- 断线与切换都会解除旧 peer 到用户的映射；新档案使用新的短会话令牌。

## 验收

- 注册产生唯一 UserID，重复账号被拒绝，正确/错误密码可区分成功与失败。
- 重启存储模块后资料仍可读取，卡牌、星级、编组、抽卡券与段位均保持。
- 未登录连接不能读写资料；已登录连接只能读写自己的资料。
- 点击主页基地可打开账号中心；UserID、切换账号、黄色新建账号、协议、音乐和音效控件均有真实行为。
- 未登录玩家可在账号中心注册或登录；登录成功会加载服务器资料，后续游戏数据变化会自动回存。
- 首次启动即连接服务器并创建默认设备账号与 UserID；手动账号登录后重启客户端，无需点击中央基地即可自动恢复同一 UserID。服务器地址变化会清除旧令牌并建立新的服务器档案；未知或已绑定安装上的错误令牌都不得伪造登录状态。
- 同一安装可以列出全部所属档案，并显示每个档案的 UserID、段位和动物数量；新建档案与切换档案后，旧档案资料不会混入新档案。
