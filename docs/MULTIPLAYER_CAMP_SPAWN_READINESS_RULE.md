# 多人营地生产就绪与满员等待规则

更新日期：2026-07-19

## 目标

让玩家能明确区分“尚未解锁的营地站点”“正常倒计时中的已建营地”“生产已就绪但队伍满员的已建营地”，并保证多个已就绪营地在腾出单位名额后公平补位。

## 状态口径

| 状态 | 条件 | 玩家可见表现 | 生产行为 |
| --- | --- | --- | --- |
| 待解锁站点 | `building == ""` | 黑色站点剪影、金币价格；点击后购买解锁 | 不进入营地生产逻辑 |
| 倒计时 | `barracks` / `hall` 且 `spawn_timer > 0` | 黄色进度条 | 计时归零后进入就绪态 |
| 可生产 | 已建营地、`spawn_timer <= 0`、本队活体数小于 `floor(72 / 当前存活势力数)` | 黄色满进度 | 权威模拟的当前 tick 立即生成绑定动物，并仅在成功后重置冷却 |
| 满员等待 | 已建营地、`spawn_timer <= 0`、本队活体数达到当前动态上限 | 琥珀色满进度与“满”标记 | 保留就绪状态，腾出名额或有势力淘汰提高上限后补位 |

## 多营地公平规则

- 多人模式使用全场 72 个活动物的总预算：每个存活势力的上限为 `floor(72 / 当前存活势力数)`，即 6/5/4/3/2/1 个存活势力时分别为 12/14/18/24/36/72。上限随淘汰即时重算，不以静默丢失或替换已有动物来强行生成。
- 满员时，就绪营地的 `spawn_timer` 可以继续小于零；负值表示该营地已经等待的时长。
- 每个权威模拟 tick 为新增动物名额选择营地时，先按绑定动物的当前实际攻击力从高到低排序；攻击相同才按 `spawn_timer` 从小到大（等待最久优先），最后按地块坐标稳定排序。卡牌等级造成的攻击差异必须计入比较。
- 每次实际生成后，才为该营地写入下一轮召唤冷却。生成技能产生的额外单位仍逐个接受单位上限检查。
- 该等待年龄直接存在于 `tiles` 快照中，因此房主权威迁移与普通快照同步无需新增协议字段。

## 战场可解锁边框层级

- 可购买且金币足够的地块使用金色六边形边框。
- 所有普通/黑色地块边框完成绘制后，才统一绘制金色可解锁边框；金色边框必须位于黑色边框之上，不能被相邻格子的黑边截断或遮住。

## 验收

1. 250 金币的黑色站点在未购买前不显示为生产中的营地，点击后才进入解锁与生产流程。
2. 本队活体数低于当前动态上限时，营地计时归零后在当前权威模拟 tick 生成绑定动物并重置冷却。
3. 本队活体数达到当前动态上限时，营地显示“满员等待”而非普通可生成满条；任意本队单位死亡释放名额，或其他势力淘汰提高上限后，下一模拟 tick 先生成当前实际攻击力最高的动物；攻击相同时才生成等待最久者。
4. 两座或更多攻击相同的已就绪营地连续获得名额时按等待顺序轮流补位，不因字典遍历顺序永久饥饿。
5. 在线非权威客户端只接收权威端结果，不自行生成或重复生成单位。
